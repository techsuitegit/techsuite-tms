# tms-web

API-only TMS backend. There is no login UI or dashboard in this repo.

This app does **not** authenticate users itself. It forwards login to hosted IAM, then uses the returned JWT to talk to a tenant PostgreSQL database.

**Stack:** Node.js `http` (login + Shipping Point on port 3001), Next.js 16 App Router (users / crypto / db session on port 3000), TypeScript, `pg`, Prisma 7 (client generate only), PostgreSQL.

**Repo:** https://github.com/techsuitegit/techsuite-tms

---

## What you get after setup

| Method | Path | Auth | Purpose |
|---|---|---|---|
| `GET` | `/` | none | API index |
| `POST` | `/api/v1/jwt/login` | none | Forward login to IAM, return `accessToken` |
| `GET` / `POST` | `/api/v1/auth/users` | Bearer | List IAM `users` from tenant DB (no passwords) |
| `POST` | `/api/v1/db/session` | Bearer | Ping tenant DB |
| `POST` | `/api/v1/crypto/encrypt` | Bearer | AES-encrypt `{ "data": ... }` |
| `POST` | `/api/v1/crypto/decrypt` | Bearer | AES-decrypt `{ "data": "<cipher>" }` |

Default login + Shipping Point URL: [http://localhost:3001](http://localhost:3001). Tenant helpers (users / crypto / db session): [http://localhost:3000](http://localhost:3000).

**Postman:** import `postman/tms-login-shipping-point.postman_collection.json` (Login + all Shipping Point APIs). See [How to test Login and Shipping Point](#how-to-test-login-and-shipping-point).

## Request flow

```text
Client
  POST /api/v1/jwt/login
    → this app
      → IAM  POST https://txiam.techsuitesystems.com/api/v1/jwt/login
    ← accessToken (JWT, claim cnn = encrypted DB credentials)

Client
  GET /api/v1/auth/users
  Authorization: Bearer <accessToken>
    → this app
      → if DEMO_TENANT_DB=true: connect to local tms_master from .env
      → if DEMO_TENANT_DB=false: decrypt JWT cnn, connect to that database
    ← { items, total }
```

IAM field names are `producttype` and `enviroment` (that spelling). `environment` is ignored.

## 1. Prerequisites

Install these first:

- **Node.js 20+** (22 or 24 is fine) and npm
- **Git**
- **PostgreSQL 14+** listening on `localhost:5432`
- Network access to IAM: `https://txiam.techsuitesystems.com`

Check:

```bash
node -v
npm -v
psql --version
```

On Windows, `psql` is optional if you use pgAdmin. A `postgres` role that can create databases is enough.

## 2. Clone and install

```bash
git clone https://github.com/techsuitegit/techsuite-tms.git
cd techsuite-tms
npm ci
```

`npm ci` also runs `prisma generate` (see `postinstall`). If generate fails, run it yourself after `.env` exists:

```bash
npx prisma generate
```

**Do not** run `npx prisma migrate` or `npx prisma db push`. `prisma/schema.prisma` is documentation of a TMS table set. Tenant data for this backend is queried with SQL against IAM-style `users`. Apply SQL yourself.

## 3. Create the local demo database

For first-time local testing this app uses database **`tms_master`**, schema **`public`**, table **`users`**.

In `psql` as a superuser (password is whatever you set for the `postgres` role):

```sql
CREATE DATABASE tms_master;
```

Connect to it:

```bash
psql -U postgres -d tms_master
```

```sql
CREATE TABLE IF NOT EXISTS public.users (
  id            integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name          varchar NOT NULL,
  user_type     varchar NOT NULL,
  shortname     varchar,
  login_access  varchar NOT NULL,
  password      varchar,
  phone         varchar,
  mobile        varchar,
  status        varchar NOT NULL DEFAULT 'Active',
  created_at    timestamp WITHOUT TIME ZONE DEFAULT now(),
  updated_at    timestamp WITHOUT TIME ZONE DEFAULT now()
);

INSERT INTO public.users (name, user_type, shortname, login_access, status)
VALUES
  ('Balan', 'CLIENT', 'Balan', 'balan@gmail.com', 'Active'),
  ('Arun',  'CLIENT', 'Arun',  'arun@gmail.com',  'Active')
ON CONFLICT DO NOTHING;
```

The users API never returns `password`.

If you already have `tms_master` with this table, skip the DDL.

## 4. Create `.env`

`.env` is gitignored. Create it in the **repo root** (same folder as `package.json`).

Copy this template and replace placeholders. Do not commit this file.

```env
# --- App ---
PRODUCT_TYPE=TMS
ENVIRONMENT=DEV

# --- Prisma generate (not used for tenant queries in demo mode) ---
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_SCHEMA=public
POSTGRES_DB=txpoprdb
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_postgres_password

# --- Secrets (use your own values, 32+ characters) ---
JWT_ACCESS_SECRET=change-me-access-secret-32chars-min
JWT_REFRESH_SECRET=change-me-refresh-secret-32chars-min
JWT_PASSWORD_RESET_SECRET=change-me-reset-secret-32chars-min
AES_LEGACY_PASSWORD=change-me-aes-legacy-password-32chars
JWT_ACCESS_EXPIRES_IN=30m
JWT_REFRESH_EXPIRES_IN=7d
JWT_PASSWORD_RESET_EXPIRES_IN=1h

# --- URLs ---
NEXT_PUBLIC_BASE_API_URL=http://localhost:3000/api
ALLOWED_ORIGINS=http://localhost:3000

# --- IAM (hosted identity) ---
IAM_API_BASE_URL=https://txiam.techsuitesystems.com/api
IAM_PRODUCT_TYPE=TMS
IAM_ENVIRONMENT=DEV

# --- Demo tenant DB (local testing) ---
# true  = ignore JWT cnn; always use DEMO_DB_* below
# false = decrypt cnn from the IAM JWT and connect to that database
DEMO_TENANT_DB=true
DEMO_DB_SERVER=localhost
DEMO_DB_PORT=5432
DEMO_DB_NAME=tms_master
DEMO_DB_SCHEMA=public
DEMO_DB_USER=postgres
DEMO_DB_PASSWORD=your_postgres_password
```

Notes:

- `AES_LEGACY_PASSWORD` must match the key IAM used to encrypt `cnn`. Wrong key → decrypt fails when `DEMO_TENANT_DB=false`.
- `IAM_PRODUCT_TYPE` / `IAM_ENVIRONMENT` are used only when the login body omits `producttype` / `enviroment`.
- Mail / SMTP variables are unused by the current APIs. You can omit them.

## 6. Smoke test

### Index

```bash
curl http://localhost:3000/
```

Expect JSON listing the API paths.

### Login (IAM)

`POST` body keys must be `producttype`, `enviroment`, `login`, `password`.

```bash
curl -s -X POST http://localhost:3001/api/v1/jwt/login ^
  -H "Content-Type: application/json" ^
  -d "{\"producttype\":\"TMS\",\"enviroment\":\"DEV\",\"login\":\"YOUR_IAM_LOGIN\",\"password\":\"YOUR_IAM_PASSWORD\"}"
```

Git Bash / macOS / Linux: replace `^` with `\` and drop the extra quotes around JSON.

Success (`200`):

```json
{
  "accessToken": "<jwt>",
  "refreshToken": "...",
  "user": { "fullName": "...", "email": "...", "role": "..." }
}
```

Common failures:

| Status | Meaning |
|---|---|
| `400` | Missing login/password, or invalid JSON (`Invalid Arguments`) |
| `401` | IAM rejected credentials, or wrong `producttype` / `enviroment` |
| `502` | IAM unreachable, or response had no token |

Login does **not** use local `tms_master`. It always calls hosted IAM.

### Ping tenant DB

```bash
curl -s -X POST http://localhost:3000/api/v1/db/session ^
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

Expect `connected: true`, `source: "demo"` when `DEMO_TENANT_DB=true`.

### List users

```bash
curl -s http://localhost:3000/api/v1/auth/users ^
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

Expect `{ "items": [ ... ], "total": N }` with `login_access`, `user_type`, `status`. No `password` field.

`401` = missing/expired Bearer. `502` = cannot read `users` (wrong DB, table missing, or Postgres down).

### Crypto

```bash
curl -s -X POST http://localhost:3000/api/v1/crypto/encrypt ^
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" ^
  -H "Content-Type: application/json" ^
  -d "{\"data\":\"hello\"}"
```

```bash
curl -s -X POST http://localhost:3000/api/v1/crypto/decrypt ^
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" ^
  -H "Content-Type: application/json" ^
  -d "{\"data\":\"CIPHER_FROM_ENCRYPT\"}"
```

Body key is **`data`** (not `value`). GET on these routes returns `405`.

## 7. Demo DB vs JWT `cnn`

| `DEMO_TENANT_DB` | Tenant connection |
|---|---|
| `true` (default) | `.env` `DEMO_DB_*` → usually `localhost` / `tms_master` |
| `false` | Decrypt JWT claim `cnn` with `AES_LEGACY_PASSWORD`, then connect using `{ db_server, db_port, db_name, db_defaultschema, db_user, db_password }` |

Keep `true` until local `tms_master` works. Switch to `false` only when IAM `cnn` points at a reachable Postgres and the AES password is correct.

Restart `npm run dev` after changing `.env`.

## 8. Shipping Point MDM (Node API)

IAM users stay in **`tms_master.public`**. Shipping Point does **not**.

| Item | Value |
|---|---|
| Database | `txpoprdb` (`POSTGRES_DB`) |
| Schema | `branch` (not `public`) |
| Tables | `branch.shipping_point`, versions, audit |
| Process | `npm run api` → http://localhost:3001 |

```bash
npm run api:sql
npm run api
```

`api:sql` creates `txpoprdb` if missing and creates schema `branch` inside it. Do not put Shipping Point tables in `tms_master`.

## How to test Login and Shipping Point

Login and Shipping Point are the **same Node process**:

| What | Command | URL |
|---|---|---|
| Login + Shipping Point MDM | `npm run api` | http://localhost:3001 |
| Create `txpoprdb.branch` (once) | `npm run api:sql` | — |
| Users / crypto / db session (optional) | `npm run dev` | http://localhost:3000 |

### Import Postman

1. Open Postman → **Import** → `postman/tms-login-shipping-point.postman_collection.json`
2. Collection variables:
   - `login` / `password` — your IAM user
   - `producttype` = `TMS`, `enviroment` = `DEV` (that spelling)
   - `divisionId` — UUID from Postgres (see below)
3. Run **Login — get accessToken** first. It stores `{{token}}`.
4. Run Shipping Point requests in numbered order.

```sql
-- on database txpoprdb
select id, code, status from branch.division where code = 'DIV-SEED-01';
```

Paste `id` into collection variable `divisionId`.

### Login API

This app does **not** check passwords. It forwards the body to hosted IAM and returns their JWT.

| | |
|---|---|
| Method | `POST` |
| Full URL | `http://localhost:3001/api/v1/jwt/login` |
| Auth | none |
| Header | `Content-Type: application/json` |

**Body**

```json
{
  "producttype": "TMS",
  "enviroment": "DEV",
  "login": "your.email@company.com",
  "password": "your-password"
}
```

Use **`enviroment`**, not `environment`.

**Success `200`**

```json
{
  "accessToken": "<jwt>",
  "refreshToken": "...",
  "user": { "fullName": "...", "email": "...", "role": "..." }
}
```

Put `accessToken` in header `Authorization: Bearer <jwt>` for every Shipping Point call.

| Status | When |
|---|---|
| 400 | Missing login/password, or invalid JSON (`Invalid Arguments`) |
| 401 | IAM rejected the user, or wrong `producttype` / `enviroment` |
| 502 | IAM host unreachable, or no token in the IAM reply |

### Shipping Point APIs (12)

Base: `http://localhost:3001`  
Header on all except health: `Authorization: Bearer {{token}}`  
Data lives in **`txpoprdb.branch`**, not `tms_master`.

Do not put the words **Depot** or **Dispatch Centre** in `name` or `address`. Type value `CYLINDER_DEPOT` is allowed.

**Enums**

- `type`: `BULK_PLANT` \| `TERMINAL_RACK` \| `YARD` \| `CYLINDER_DEPOT`
- `reason`: `Correction` \| `New record` \| `Regulatory update` \| `Commercial change`
- `status`: `DRAFT` \| `PENDING` \| `PUBLISHED` \| `REJECTED` \| `ARCHIVED`

Submit is **AUTO**: DRAFT becomes **PUBLISHED** immediately (no approver queue). Approve/reject exist for the contract; they return `409` unless status is `PENDING`.

#### Health (no token)

`GET http://localhost:3001/health`

```json
{ "ok": true, "name": "tms-mdm-api" }
```

#### 1. Create — `POST /api/v1/mdm/shipping-points`

Required: `code`, `name`, `divisionId`, `type`, `address`, `latitude`, `longitude`, `validFrom`, `reason`.

```json
{
  "code": "SP-CHE-01",
  "name": "Chennai Plant Shipping Point",
  "divisionId": "<uuid from branch.division>",
  "type": "BULK_PLANT",
  "address": "Manali, Chennai",
  "latitude": 13.1667,
  "longitude": 80.2667,
  "geofenceRadiusM": 150,
  "openingHours": "06:00-22:00",
  "loadingBays": 4,
  "loadingRateLpm": 1200.5,
  "midShiftReload": true,
  "productsStocked": ["MS", "HSD"],
  "leadDispatcher": "Kumar",
  "phone": "+914412345678",
  "hazmatClass": "3",
  "permitNo": "TN-SP-2026-01",
  "permitExpiry": "2027-03-31",
  "erpRef": "ERP-CHE-01",
  "validFrom": "2026-04-01",
  "validTo": null,
  "reason": "New record",
  "changeNote": "Initial create",
  "externalId": null
}
```

**201** `{ "id": "...", "status": "DRAFT", "versionNo": 1 }`

Invalid lat (`99`) → **400** `{ "code": "VALIDATION", "field": "latitude" }`

#### 2. List — `GET /api/v1/mdm/shipping-points`

Query (all optional): `q`, `status`, `page`, `pageSize`, `sort` (`code` \| `name` \| `status` \| `validFrom` \| `updatedAt`).

**200** `{ "items": [], "total": 0, "page": 1 }`

#### 3. Get one — `GET /api/v1/mdm/shipping-points/:id`

**200** full record + division labels. **404** if the id is missing.

#### 4. Submit — `POST /api/v1/mdm/shipping-points/:id/submit`

```json
{ "reason": "New record" }
```

**200** `{ "status": "PUBLISHED" }`

#### 5. Lookups — `GET /api/v1/mdm/lookups/shipping-points`

Published-only dropdown: `[{ "id", "code", "name" }]`. Empty until you submit.

#### 6. Patch — `PATCH /api/v1/mdm/shipping-points/:id`

Send **the same fields as create plus `versionNo`** (current value from Get one). Wrong version → **409** `STALE_VERSION`.

```json
{
  "code": "SP-CHE-01",
  "name": "Chennai Plant Shipping Point",
  "divisionId": "<uuid>",
  "type": "BULK_PLANT",
  "address": "Manali, Chennai",
  "latitude": 13.17,
  "longitude": 80.27,
  "validFrom": "2026-04-01",
  "reason": "Correction",
  "changeNote": "Updated coordinates",
  "versionNo": 2
}
```

Optional fields from create may be included the same way. **200** `{ "id", "versionNo" }`.

#### 7. Versions — `GET /api/v1/mdm/shipping-points/:id/versions`

**200** `{ "versions": [{ "versionNo", "snapshot", "recordedAt", "recordedBy" }] }`

#### 8. Audit — `GET /api/v1/mdm/shipping-points/:id/audit`

**200** `{ "events": [{ "action", "actor", "note", "payload", "createdAt" }] }`

#### 9. Export — `GET /api/v1/mdm/shipping-points/export`

CSV of PUBLISHED + DRAFT rows (`shipping-points.csv`).

#### 10. Import — `POST /api/v1/mdm/shipping-points/import`

`Content-Type: application/json`

```json
[
  {
    "code": "SP-CHE-02",
    "name": "Chennai Rack Shipping Point",
    "divisionId": "<uuid>",
    "type": "TERMINAL_RACK",
    "address": "Ennore, Chennai",
    "latitude": 13.2,
    "longitude": 80.32,
    "validFrom": "2026-04-01",
    "reason": "New record"
  }
]
```

Or `Content-Type: text/csv` with the same column names. XLSX is not accepted.  
**200** `{ "accepted": [{ "id", "code" }], "rejected": [{ "row", "message", "field" }] }` (row-level, not all-or-nothing).

#### 11. Approve — `POST /api/v1/mdm/shipping-points/:id/approve`

```json
{ "note": "Approved" }
```

Only if status is `PENDING`. After AUTO submit expect **409**.

#### 12. Reject — `POST /api/v1/mdm/shipping-points/:id/reject`

```json
{ "note": "Missing permit details" }
```

`note` is mandatory. Only `PENDING`. After AUTO submit expect **409**.

### Common Shipping Point errors

| Status | Meaning |
|---|---|
| 401 | Missing or invalid Bearer token — run Login first |
| 400 + `field` | Validation (lat/long, missing field, Depot wording, unpublished Division) |
| 404 | Unknown UUID |
| 409 | Duplicate `code` / `externalId`, or stale `versionNo`, or wrong status for approve/reject |

Suggested Postman order: **Health → Login → Create → invalid lat → List → Get → Submit → Lookup → Patch → Versions → Audit → Export → Import**.

## 10. Troubleshooting

| Problem | What to check |
|---|---|
| `EADDRINUSE :::3000` | Another `npm run dev` is running. Stop it. |
| `EADDRINUSE :::3001` | Another `npm run api` is running. Stop it. |
| Shipping Point 401 | Run Login on :3001 and send `Authorization: Bearer` on the same host. |
| Create 400 `divisionId` | Paste a PUBLISHED UUID from `txpoprdb.branch.division` (`DIV-SEED-01`). |
| Login `401 Invalid Arguments` | JSON invalid, or IAM rejected the body. Use `enviroment` not `environment`. |
| Login `401 Invalid login` | Wrong IAM user/password, or `producttype` not `TMS` with `enviroment` `DEV`. |
| Users `401 Bearer token is required` | Send `Authorization: Bearer <accessToken>` from login. |
| Users `502 users table was not found` | Connected DB has no `public.users`. Create it in `tms_master`. |
| Users `502 Unable to read users` | Postgres down, wrong `DEMO_DB_PASSWORD`, or `DEMO_TENANT_DB=false` and `cnn` host is unreachable. |
| Crypto `401` | Same Bearer requirement as users. |
| Decrypt fails | `AES_LEGACY_PASSWORD` does not match the key that produced the cipher / `cnn`. |
| Prisma generate errors | `.env` `POSTGRES_*` can stay dummy for demo mode; generate does not need `tms_master`. |
